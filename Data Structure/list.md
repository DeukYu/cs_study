# list
> 📌 기출: [NC Project NL Q7, Q12](../Interview/NC_Project_NL_%EB%A9%B4%EC%A0%91_%EC%A7%88%EB%AC%B8.md) - list의 메모리 관리 / vector와 다르게 발생할 수 있는 문제

- `std::list`는 **이중 연결 리스트 (Doubly Linked List)**
- 원소마다 노드(`prev`, `next`, `value`)를 **하나씩 개별 할당** 합니다.
- 구현에 따라 sentinel(더미) 노드를 두고 원형으로 연결합니다.

---

## 메모리 구조 (Q7)
```
       ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
 ◀──── │ prev|val|next│ ◀─▶ │ prev|val|next│ ◀─▶ │ prev|val|next│ ────▶
       └──────────────┘     └──────────────┘     └──────────────┘
         0x1A00 (힙)          0x7F40 (힙)          0x3C20 (힙)
```
- 노드가 힙 여기저기 흩어져 있습니다.
- 원소당 포인터 2개(64비트 기준 16B) + 할당자 헤더만큼 메모리가 추가로 듭니다.

---

## 시간 복잡도
|연산|복잡도|
|---|---|
|임의 접근|O(n)|
|위치를 알 때 삽입/삭제|O(1)|
|탐색|O(n)|
|splice (다른 list로 노드 이동)|O(1), 할당 없음|

- 삽입/삭제 시 **다른 원소의 반복자가 무효화되지 않는 것** 이 가장 큰 장점입니다.

---

## vector와 다르게 발생하는 문제 (Q12)
- 핵심은 **원소를 넣을 때마다 작은 new/delete가 일어난다** 는 것입니다.

1. **할당 비용 누적**: 할당 횟수 자체가 많아 할당자 비용이 쌓이고, 멀티스레드면 힙 락 경합이 생깁니다. ([멀티스레드_메모리_할당](../Operating%20System/%EB%A9%80%ED%8B%B0%EC%8A%A4%EB%A0%88%EB%93%9C_%EB%A9%94%EB%AA%A8%EB%A6%AC_%ED%95%A0%EB%8B%B9.md))
2. **힙 단편화**: 작은 블록이 흩어져 단편화가 생깁니다.
3. **메모리 오버헤드**: 포인터/헤더 때문에 실제 데이터보다 메모리를 훨씬 많이 씁니다. (`list<int>`는 원소당 실제 데이터 4B에 오버헤드 20B 이상)
4. **캐시 지역성 저하**: 순회/조회가 느립니다. ([vector_vs_list](./vector_vs_list.md))

### 대응
- 노드 풀 / 전용 Allocator 사용
- 대부분의 경우 `vector`나 `deque`로 대체하는 것이 더 빠릅니다. 반복자 안정성이 꼭 필요할 때만 list를 씁니다.
