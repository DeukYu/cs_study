# 메모리 얼라인먼트 (Memory Alignment)
> 📌 기출: [NC Project NL Q1](../Interview/NC_Project_NL_%EB%A9%B4%EC%A0%91_%EC%A7%88%EB%AC%B8.md) - 메모리 얼라인먼트가 무엇인가?

- 데이터를 자기 크기(혹은 요구 정렬값)의 **배수 주소** 에 배치하는 규칙
- CPU는 메모리를 바이트 단위가 아니라 워드/캐시라인(보통 64B) 단위로 읽기 때문에 필요합니다.

---

## 왜 필요한가
- 정렬이 어긋나면 한 번에 읽을 데이터를 **두 번** 읽거나, **캐시라인 경계** 를 걸치게 됩니다.
- 일부 아키텍처(구형 ARM 등)는 비정렬 접근 시 예외가 발생합니다.
- atomic 연산은 정렬되어 있어야 원자성이 보장됩니다.

---

## 구조체 패딩
- 멤버 사이에 **패딩(padding)** 이 들어가고, 구조체 전체 크기는 가장 큰 멤버 정렬값의 배수가 됩니다.

```cpp
struct A {        // sizeof(A) == 24
    char   c;     // 1 + 패딩 7
    double d;     // 8
    int    i;     // 4 + 패딩 4
};

struct B {        // sizeof(B) == 16
    double d;     // 8
    int    i;     // 4
    char   c;     // 1 + 패딩 3
};
```
- 멤버를 **큰 타입 순** 으로 배치하면 패딩을 줄일 수 있습니다.

---

## 제어 방법
|방법|설명|
|---|---|
|`alignof(T)`|타입의 정렬 요구값 조회|
|`alignas(N)`|변수/타입을 N바이트 경계에 정렬|
|`#pragma pack(1)`|패딩 제거. 패킷 구조체에 사용하지만 접근 비용과 비정렬 접근 위험 존재|

---

## 실무 포인트
- **False Sharing 방지**: 스레드별로 자주 쓰는 변수는 `alignas(64)`로 캐시라인을 분리합니다. ([Atomic과_캐시_일관성](./Atomic%EA%B3%BC_%EC%BA%90%EC%8B%9C_%EC%9D%BC%EA%B4%80%EC%84%B1.md))
- **SIMD**: SSE/AVX 연산은 16B/32B 정렬이 필요합니다.
- **네트워크 패킷**: `pack(1)`으로 송수신 구조를 맞추되, 직렬화 계층에서 복사해 쓰는 것이 안전합니다.
