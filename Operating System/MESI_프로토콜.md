# MESI 프로토콜 (캐시 일관성)
> 📌 연관 기출: [NC Project NL Q5](../Interview/NC_Project_NL_%EB%A9%B4%EC%A0%91_%EC%A7%88%EB%AC%B8.md) - atomic 경합 질문의 핵심 개념 ([Atomic과_캐시_일관성](./Atomic%EA%B3%BC_%EC%BA%90%EC%8B%9C_%EC%9D%BC%EA%B4%80%EC%84%B1.md))

- **코어마다 따로 가진 캐시들이 서로 다른 값을 보지 않게 맞추는 규칙**
- 캐시라인(64B)마다 상태 꼬리표를 붙이는데, 그 4가지 상태의 앞글자를 딴 이름입니다.
- 하드웨어가 자동으로 지켜주는 규칙이라 직접 다룰 일은 없지만, **핑퐁, False Sharing 같은 성능 문제를 설명할 때** 꼭 등장합니다.

---

## 왜 필요한가
- 코어 A와 B가 둘 다 `x = 0`을 자기 캐시에 복사해뒀다고 가정합니다.
- A가 `x = 5`로 바꿨는데 B의 캐시에는 아직 0이 남아 있으면, **B는 틀린 값을 읽게 됩니다.**
- 이를 막으려면 "누가 이 데이터를 갖고 있고, 그게 최신인지"를 추적해야 하고, 그 추적 장부가 MESI입니다.

---

## 4가지 상태
> 공용 문서를 각자 복사해서 책상에 두는 상황으로 비유

|상태|뜻|비유|읽기|쓰기|
|---|---|---|---|---|
|**M** (Modified)|나만 갖고 있고, **내가 고쳤음**|내 책상에만 있고, 수정해서 원본과 다름|O|O (바로)|
|**E** (Exclusive)|나만 갖고 있고, 원본과 같음|내 책상에만 있고, 아직 안 고침|O|O (바로, 고치면 M)|
|**S** (Shared)|여러 명이 갖고 있음|여러 명이 읽기용 복사본을 가짐|O|X (남의 것을 먼저 버리게 해야 함)|
|**I** (Invalid)|내 복사본은 무효|옛날 거라 버린 상태|X|X|

### 핵심 규칙
- **쓰려면 나 혼자 가져야 한다 (M 또는 E).**
- 여러 명이 갖고 있으면(S), 다른 코어들의 복사본을 전부 **I(무효)** 로 만든 뒤에야 쓸 수 있습니다.

---

## 예시로 따라가기
> 변수 `x` 하나를 코어 A, B가 다루는 경우

|순서|일어난 일|A 상태|B 상태|
|---|---|---|---|
|1|A가 `x`를 읽음 (아무도 안 갖고 있었음)|**E**|I|
|2|B도 `x`를 읽음|**S**|**S**|
|3|A가 `x = 5`로 쓰려 함 → B에게 "네 거 버려" (Invalidate)|**M**|**I**|
|4|B가 `x`를 다시 읽음 → A가 최신 값 5를 넘겨줌|**S**|**S**|
|5|B가 `x = 6`으로 쓰려 함 → A에게 "네 거 버려"|**I**|**M**|

- 3번, 5번처럼 **쓰기가 일어날 때마다 다른 코어의 복사본이 무효화** 되는 것이 핵심입니다.

---

## 상태 전이 요약
|현재 상태|내가 읽음|내가 씀|다른 코어가 읽음|다른 코어가 씀|
|---|---|---|---|---|
|M|M 유지|M 유지|값 전달 후 **S**|값 전달 후 **I**|
|E|E 유지|**M** (알릴 필요 없음)|**S**|**I**|
|S|S 유지|다른 코어 무효화 후 **M**|S 유지|**I**|
|I|가져옴 → 혼자면 **E**, 아니면 **S**|가져오며 다른 코어 무효화 → **M**|-|-|

---

## 관련 용어
|용어|쉬운 설명|
|---|---|
|캐시라인 (Cache Line)|캐시가 데이터를 옮기는 최소 단위, 보통 64바이트. MESI 상태도 이 단위로 붙음|
|Invalidate (무효화)|"네가 가진 복사본은 옛날 거니까 버려"|
|RFO (Read For Ownership)|"그 캐시라인 나한테 넘겨줘, 내가 고칠 거야" 요청|
|Snoop (스누프)|다른 코어들이 RFO 같은 요청을 엿듣고 반응하는 것|
|Snoop Filter / Directory|모든 코어에 다 물어보지 않도록, "누가 이 라인을 갖고 있는지" 기록해둔 장부 (보통 L3 쪽)|
|Write-back|M 상태 라인은 바로 메모리에 쓰지 않고, 쫓겨날 때(evict) 메모리에 씀|

## 성능 문제와의 연결
### Cache Line Ping-Pong
- 여러 코어가 **같은 캐시라인에 계속 쓰면**, M 상태가 코어 사이를 계속 옮겨 다닙니다.
- 옮길 때마다 "버려라" + "최신 값 보내라" 메시지가 오가서 느려집니다.
- 예: 32개 스레드가 `atomic` 변수 하나에 `fetch_add` → [Atomic과_캐시_일관성](./Atomic%EA%B3%BC_%EC%BA%90%EC%8B%9C_%EC%9D%BC%EA%B4%80%EC%84%B1.md)

### False Sharing
- **서로 다른 변수** 인데 같은 64B 캐시라인 안에 있으면, MESI는 라인 단위로 동작하므로 **괜히 같이 무효화** 됩니다.

```cpp
struct Counters {
    std::atomic<int> a;   // 스레드 1이 씀
    std::atomic<int> b;   // 스레드 2가 씀  → 같은 캐시라인이라 서로 무효화
};

struct PaddedCounters {
    alignas(64) std::atomic<int> a;   // 캐시라인 분리
    alignas(64) std::atomic<int> b;
};
```
- 해결: `alignas(64)`로 캐시라인을 분리합니다. ([메모리_얼라인먼트](./%EB%A9%94%EB%AA%A8%EB%A6%AC_%EC%96%BC%EB%9D%BC%EC%9D%B8%EB%A8%BC%ED%8A%B8.md))

### 읽기는 공유, 쓰기는 독점
- **읽기만 하는 데이터** 는 여러 코어가 S 상태로 동시에 가질 수 있어 빠릅니다.
- **자주 쓰는 데이터** 를 여러 코어가 공유하면 느려집니다.
- 그래서 멀티스레드 설계의 기본은 "**공유하려면 읽기 전용으로, 쓰려면 스레드별로 분리**"입니다.

## 변형 프로토콜
|프로토콜|사용처|추가 상태|역할|
|---|---|---|---|
|MESI|기본형|-|-|
|MESIF|Intel|**F** (Forward)|S 상태 코어가 여럿일 때 **대표로 값을 보내줄 코어** 를 정함. 응답 중복 방지|
|MOESI|AMD|**O** (Owned)|고친 값을 메모리에 쓰지 않고도 **다른 코어와 공유** 가능. 메모리 쓰기 감소|

- 기본 원리는 모두 같습니다. "쓰기 전에 다른 복사본을 무효화한다."

---

## 면접 답변
> "코어마다 캐시가 따로 있어서 같은 데이터의 값이 어긋날 수 있는데, 이를 막기 위해 캐시라인마다 Modified, Exclusive, Shared, Invalid 상태를 두고, **쓰기 전에 다른 코어의 복사본을 무효화** 해서 일관성을 맞추는 프로토콜입니다. 그래서 여러 코어가 같은 캐시라인에 계속 쓰면 소유권이 계속 옮겨 다니는 핑퐁이 생기고, 서로 다른 변수라도 같은 캐시라인에 있으면 False Sharing이 발생합니다."
