# Context Switching
> 📌 기출: [NC Project NL Q3](../Interview/NC_Project_NL_%EB%A9%B4%EC%A0%91_%EC%A7%88%EB%AC%B8.md) - Context Switching은 언제 발생하는가?

- CPU가 실행 중인 스레드(프로세스)의 상태를 저장하고, 다른 스레드의 상태를 불러와 실행을 이어가는 것
- 저장/복원되는 상태(Context): 레지스터, 프로그램 카운터(PC), 스택 포인터, (프로세스 전환이면) 페이지 테이블 정보

---

## 발생 시점
1. **자발적 전환 (Voluntary)**
    - 스레드가 스스로 CPU를 내놓는 경우
    - 블로킹 I/O, 락 대기(mutex, condition variable), `Sleep`, `WaitForSingleObject`, `yield`

2. **비자발적 전환 (Involuntary)**
    - 스케줄러가 강제로 CPU를 뺏는 경우
    - **타임 슬라이스(퀀텀) 소진**
    - 더 높은 우선순위 스레드가 깨어남 (**선점, Preemption**)
    - 인터럽트 처리 후 스케줄러가 다시 호출될 때

---

## 비용
- 레지스터 저장/복원, 유저 모드 ↔ 커널 모드 전환
- **캐시와 분기 예측 오염**: 새 스레드는 차가운 캐시에서 시작하므로 전환 직후가 느립니다. 실제로는 이 간접 비용이 더 큽니다.
- **프로세스 간 전환이 더 비싼 이유**: 주소 공간이 바뀌어 페이지 테이블 레지스터(CR3)가 교체되고 **TLB가 플러시** 됩니다. 같은 프로세스 내 스레드 전환은 주소 공간이 같아 상대적으로 쌉니다.

|구분|스레드 전환|프로세스 전환|
|---|---|---|
|레지스터 저장/복원|O|O|
|주소 공간 교체|X|O|
|TLB 플러시|X|O (PCID 지원 시 완화)|
|비용|상대적으로 낮음|높음|

---

## 서버 개발 관점
- 스레드를 코어 수보다 훨씬 많이 두거나 락 경합이 심하면 전환이 급증합니다.
- IOCP 워커 스레드 수를 코어 수에 맞추는 이유가 이것입니다.
- 짧은 임계 영역은 커널 대기로 빠지지 않도록 SpinLock / SRWLock을 사용합니다.
